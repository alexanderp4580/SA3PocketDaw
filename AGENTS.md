# sa3BrowserDaw

## Purpose

Proof-of-concept phone DAW in the browser: Stable Audio 3 generates instrument samples on-device, a piano roll plays them. Hosted from the Steam Deck for sharing. Design: `docs/design.md`.

## Ownership

- `docs/`: design, handoff, resume and compatibility notes. `spikes/`: feasibility scripts and measured evidence. `src/`: app. `server/`: static HTTPS host. `scripts/`: model manifest and instrument pack helpers. `models/`: local model and instrument-pack files, ignored; deployed ones are fetched from Hugging Face (`VITE_MODELS_BASE_URL`). `public/instruments/mini-piano/`: bundled preset. `certs/`, `dist/`, `node_modules/`: ignored.

## Local Contracts

- The host only serves static files. Optional cloud generation calls Stability AI's API directly from the browser with the user's own key, stored only in that browser's localStorage; the key never appears in logs, the Debug report, errors, the project, IndexedDB, sample metadata or exports, and the service worker never handles `api.stability.ai` requests.
- Everything needed after the first visit must work offline; model files come from Cache Storage once installed.
- Mobile first, portrait only; every action has a visible button; no swipe actions.
- Every module logs through `src/log`; the Debug screen and report must show real data.
- Docs and comments describe only what exists now; no mentions of removed or replaced things.
- Unverified device or API claims are marked "to check".
- Never add co-author trailers to commits.

- Model files live in Cache Storage `sa3-models-v1`; the manifest copy in `sa3-manifest-v1`. `clearAllAppData` runs hooks registered with `addClearHook`; project and sample stores register theirs.

- `src/melody/` converts standalone SA3 piano takes into sixteenth-step notes, preserves notes outside the selected bars, and builds preview projects retaining all instrument source references. `src/app/GenerateBarsSheet.svelte` orchestrates local/cloud generation, on-device transcription, preview and Keep/Discard; PianoRoll owns the single undo entry. `?demo=1` seeds a real take only for a fresh project.

- Follow song (`docs/context-generation.md`): `src/melody/context.ts` plans phase-correct piano context and removes pitch/onset matches; `renderContext.ts` renders Mini piano and copies the first part after a silent gap, then writes PCM16 WAV; `contextPipeline.ts` sends that context through optional `CloudParams.inpaint`, crops only the gap, transcribes and quantizes it. `preview.ts` can audition with the song, retaining every instrument source. Follow song is Cloud-only and stamps the song context against stale acceptance.
