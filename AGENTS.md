# sa3BrowserDaw

## Purpose

Proof-of-concept phone DAW in the browser: Stable Audio 3 generates instrument samples on-device, a piano roll plays them. Hosted from the Steam Deck for sharing. Design: `docs/design.md`.

## Ownership

- `docs/`: design, handoff and compatibility notes. `src/`: app. `server/`: static HTTPS host. `scripts/`: manifest and model-link helpers. `models/`: local model files, ignored; deployed models are fetched from Hugging Face (`VITE_MODELS_BASE_URL`). `certs/`, `dist/`, `node_modules/`: ignored.

## Local Contracts

- No server-side inference; the host only serves static files.
- Everything needed after the first visit must work offline; model files come from Cache Storage once installed.
- Mobile first, portrait only; every action has a visible button; no swipe actions.
- Every module logs through `src/log`; the Debug screen and report must show real data.
- Docs and comments describe only what exists now; no mentions of removed or replaced things.
- Unverified device or API claims are marked "to check".
- Never add co-author trailers to commits.

## Work Guidance

- TypeScript (strict), Svelte 5, Vite, Vitest, svelte-check; style from AstraCamillaGui. Tests first for logic (Vitest, node environment; browser APIs are injected fakes).
- `onnxruntime-web` 1.27.0 and `@huggingface/transformers` 3.8.1 are pinned exactly. `npm run prepare-assets` (run by `dev` and `build`) copies the ORT WASM files into ignored `public/ort/` and checks `public/gpu-probe.onnx`.
- Commands: `npm run dev|build|test|typecheck|manifest|models:link|serve`. `models:link` symlinks the PoC model files into `models/`; `manifest` writes `models/manifest.json` (packs `encoder`, `small-music`, `medium`; `small-sfx` only when `models/small-sfx/` exists). `scripts/make-cert.sh` writes the self-signed cert; `scripts/perf-probe/` is a dev-only load probe (`probe.ts` renders the engine graph offline and reports the cost relative to real time, `app.mjs` plays an injected synthetic project in the real app and reports main-thread and note-lead numbers; both need `npx vite --port 5199` and playwright-core); `serve` listens on HTTPS 8443 and HTTP 8082 (`HTTPS_PORT`, `HTTP_PORT` override).
- Modules: `src/log` (ring-buffer logger, `log.scope(name)`, worker forwarding via `forwardLogs`/`ingestWorkerMessage`, report builder with registered providers), `src/compat` (`evaluate` pure rules, `probeEnvironment`/`runCompat` collect the real environment), `src/store/modelManager.ts` (manifest, Cache Storage install state, download, delete, persistence), `src/audio` (`samplePrep` mono 44.1 kHz trim/fade/normalize to -1 dBFS; `pitch` multi-window harmonic spectral detection plus `rootFromDetection` (C4 fallback below confidence 0.7) and note names; `trim` non-destructive chop (`Trim` {start,end} seconds of the original source, minimum 50 ms kept, `applyTrim` with 3 ms edge fades, `storedTrim` stores nothing for the full clip); `sampler` playback rate and voices over an AudioContext-like interface; `scheduler` 0.3 s look-ahead loop over a pattern with injected clock/timer, events carry velocity as 0..1 gain (`engine` skips notes delivered more than 0.1 s after their time and logs one summed warning per second); `instrument/` analyses isolated notes in a worker, prepares sinc attacks/notched noise in a small worker pool (`client`, `assetCache` keeps at most 16 to 48 prepared pitches per player and hands data to the worklet without retaining it) and plays evolving partials in an AudioWorklet (`voice` advances partials by rotation, at most 8 sounding and 16 rendering voices per track); `engine` wires sample and instrument playback (a sample buffer is the source cut to the track's trim, rebuilt only when the cut changes; `setInstrument` disposes players of that sound), context, master gain, caches and scheduler, context created on `unlock()`), `src/store/projectModel.ts` (pure immutable project/track/note helpers, notes snapped to 16ths, MIDI 24..96, velocity 1..127 with missing = 96; optional `track.trim`, cleared when a track receives a new sound, malformed values dropped on load), `src/store/projectStore.ts` (IndexedDB `sa3daw`: `project` slot `current` and `samples` by id; debounced 500 ms save with `flush()`; `subscribe` store; unreferenced samples deleted on track removal/replacement and on load; `registerClear(addClearHook)`), `src/gen` (generation: `client.ts` main-thread queue and error mapping, `worker.ts` module worker, `pipeline.ts` stage logic over the `Ports` interface, `ortRuntime.ts` the only file touching ONNX Runtime and the tokenizer, `layout.ts` manifest path resolution and graph reading, `sampling.ts`, `float16.ts`, `timing.ts`, `prompt.ts`, `protocol.ts` message types and guards), `src/app/trimSound.ts` (`applyTrackTrim`: stores a track's trim; an instrument is analysed again from the cut source and its stored profile is written only when analysis succeeds, flushed together with the trim; results for a sound the track no longer has are dropped; the stored source stays whole), `src/app/latestRunner.ts` (one async job at a time, latest queued value wins), `src/app/TrimControl.svelte` (Chop: draggable Start/End handles on the waveform with the kept region, pinch or +/−/Fit/pan-button zoom over a view window, millisecond Start/End/Kept readout, Reset; the waveform is redrawn per column from the source PCM when `ChopView` carries `pcm`+`sampleRate`; shown inside the sample and instrument control panels, commits on handle release; pure window/pixel/peak/drag maths in `src/app/chopView.ts`; draft chop is local and persisted on Use via `trimDraft`; export applies the trim to sample tracks), `src/components` (Nav, KnobDial, HSlider), `src/app/meterPoll.ts` (one shared timer for all visible meters), `src/app/screens/PianoRoll.svelte` (PocketDaw cursor-edited piano roll from `PocketDaw/docs/screens.md`: header with sample chip and undo/redo, Grid/In-key/Loop chips, info line, ruler plus key rows, D-pad | Keys play surface with velocity strip; positioned divs inside one scroll container so the sticky ruler and key column scroll with the grid; compact icon header with a purple instrument button; bottom shell transport with icon-only start/restart, Play/Pause and Reset playback controls; logic in `src/app/pianoroll`: `geometry` row/cell/ruler mapping and scroll reveal, `cursor` grid steps, in-key pitch moves, target rule, jumps, info line and velocity mapping, `edit` place/delete/length/velocity over the project helpers, `keyboard` one-octave layout, `history` undo/redo stack, `repeater` hold-to-repeat timing; `harness.html` is a dev-only page at `/src/app/pianoroll/harness.html`, not part of the build), `src/styles/theme.css`.
- `src/audio/mixer` (per-track and master insert chains): `plugins.ts` (`PluginType` = `eq`, `reverb` and the effect kinds; at most 6 ordered inserts per chain, `normalizeMix`/`normalizeChain` drop unknown types, `MASTER_ID` addresses the master chain in `addPlugin`/`movePlugin`/`removePlugin`/`setPluginBypass`/`updatePluginSettings`), `controller.ts` (`createMixer`: track buses sum into one master input, then the master insert chain, then the master volume and meter; structural changes fade through silence; project tempo reaches tempo-synced effects), `pluginNodes.ts` (one node per insert; effects run in the worklet `sa3-fx-<kind>`), `processor.ts` (worklet bundle: EQ, reverb, meter, one effect processor per kind), `fx/` (`spec.ts` parameter ids, ranges, defaults, `normalizeFx`, slider mapping and formatting; one allocation-free DSP module per effect behind `FxDsp` in `types.ts`, `registry.ts`, `host.ts` `FxHost` with click-free bypass, latency alignment and non-finite guards; limiter, compressor, delay, saturation, chorus, phaser, flanger, resonant filter, stereo widener, bitcrusher, transient shaper). `Project.masterPlugins` stores the master chain (missing = empty). Effect settings are `Record<string,number>` in spec units; choices are indices. `src/app/pluginEditor.ts` holds the pure editor logic (`masterTrack`, `fxEditorState`, `setFxParam`, `resetFx`, `visibleParams`); `FxSheet.svelte` renders any effect from its spec; EQ and reverb keep `EqSheet`/`ReverbSheet`. `src/song/render.ts` builds the same chains offline, including the master chain.
- `src/store/modelsBase.ts` is the only place that decides where models are fetched: `VITE_MODELS_BASE_URL` (build time, absolute URL, trailing slash added if missing) or else `models/` under the app base. Cross-origin fetches use `mode: 'cors'`, `credentials: 'omit'`; the service worker never handles them. The Dockerfile build stage takes `ARG VITE_MODELS_BASE_URL`.
- Model files live in Cache Storage `sa3-models-v1`; the manifest copy in `sa3-manifest-v1`. `clearAllAppData` runs hooks registered with `addClearHook`; project and sample stores register theirs.
