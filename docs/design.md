# sa3BrowserDaw design

A proof-of-concept phone DAW that runs entirely in the browser. Stable Audio 3 (SA3) generates instrument samples on the device; a piano roll plays them chromatically. Shared with other people via a page hosted on the Steam Deck.

Basis: `/home/deck/SketchBook/Projects/PocketDaw/docs/sa3-browser-poc.md` and the working PoC at `/home/deck/Documents/Codex/sa3-browser-poc` (worker code, sampler maths, GPU probe). Layout follows the PocketDaw mockups (`PocketDaw/docs/mockups/`): bottom sheets, a visible button for every action, portrait only. Visual style and component setup follow `/home/deck/SketchBook/Projects/AstraMoode/AstraCamillaGui/client` (Svelte 5, Vite, Vitest, `styles/theme.css` tokens, `KnobDial`, `HSlider`, `Nav`, icon set): copy and adapt what is needed; PocketDaw's orange accent is used for transport and the SA3 violet for generation actions.

## Confirmed requirements

- Tracks, each with one looping piano-roll pattern (1-4 bars) and one instrument sample.
- Instrument sample = SA3 output: prompt such as "synth lead" generates a short single-note sound. The app detects its pitch (root note), trims silence, and plays it at other notes by changing playback rate (sampler). No loop points.
- Single generation, auto-kept on the track; regenerate replaces it. Root note is shown and adjustable by semitone buttons.
- Melodies are hand-drawn on the piano roll. No random-melody button.
- The Mix screen has horizontal channel strips with volume, pan, Mute/Solo, stereo meters and ordered EQ/Reverb inserts (up to six per track). Master has volume and a stereo meter.
- Models, user-selectable: Small Music (Q4, about 683 MB with the shared encoder), Small SFX and Medium (about 2.29 GB). Medium is unverified on phones. No browser-ready Small SFX export exists yet: the community Q4 export covers Small Music only and the official SFX ONNX is large (about 1.8 GB DiT in bf16). A Small SFX pack must be produced by converting that export the way the PoC converted Medium (task 5); until the pack exists, the SFX choice shows as not available.
- Model files install with one Download button per model into browser storage (Cache Storage). The user is never asked to pick a folder or import a file.
- Models download once into browser storage (persistent storage requested) and are never refetched while stored. The app shell, runtime, models, project and generated audio all work with no network after the first visit.
- Whole project (tracks, notes, tempo, key, samples) autosaves and reloads on the next visit.
- Hosting: LAN, self-signed HTTPS (WebGPU needs a secure context). Others on the LAN accept a certificate warning once.
- Startup compatibility verdict that says whether the app runs in this browser and, when not, why. Debug screen with live log and reports.

## Not in scope

Export to WAV, arrangement of multiple clips, loop points, recording, MIDI, tunnelled/public hosting, accounts, any server-side inference.

## Architecture

Vite + TypeScript + Svelte 5 SPA; Vitest for logic tests. Production build is static files under `dist/`. `server/serve.mjs` serves `dist/` and `/models/` over HTTPS (self-signed cert in ignored `certs/`) with an HTTP port for local use. It runs no inference.

```
src/
  app/        Svelte UI: screens, sheets, components, theme (css)
  audio/      AudioContext, sample voice, scheduler, pitch detection, sample prep
  gen/        SA3 generation: main-thread client + module worker (ported from the PoC)
  store/      project model, IndexedDB persistence, model manager (Cache Storage), storage persistence
  compat/     capability probes and verdict rules
  log/        ring-buffer logger, report builder
public/       ort/ (ONNX Runtime WASM), gpu-probe.onnx, icons, manifest, service worker source
models/       ignored; links to PoC model files; manifest.json generated by script
```

### Models and offline storage

- `scripts/make-manifest.mjs` writes `models/manifest.json`: packs with file lists and byte sizes. Packs: `encoder` (tokenizer + text_encoder_q4, shared), `small-music` (number_conditioner, dit_q4, decoder_q4), `small-sfx` (same layout, converted per task 5; listed only when its files exist), `medium` (dit_q4, decoder_fp16 from `models-medium`). Each model = encoder + its own pack. The unused FP16 diffusion graph and `dec_fp16.onnx` are never packaged.
- Model manager downloads each file with progress, verifies byte size, writes to Cache Storage (`sa3-models-v1`), calls `navigator.storage.persist()`, reports `navigator.storage.estimate()`. A pack is "installed" only when all files are present and sized correctly. Delete per pack. Resumable at file granularity.
- Generation worker reads files from Cache Storage; it never hits the network for model files once installed.
- The loaded SA3 sessions stay resident in the worker between generations (Small: all sessions; Medium: sessions are released between stages as in the PoC to limit memory). A "Free model memory" button unloads them.
- A service worker precaches the app shell and ONNX Runtime WASM so the page opens offline. It adds `Cross-Origin-Opener-Policy`/`Cross-Origin-Embedder-Policy` to responses it serves. WASM thread count: 1 on Android and whenever not cross-origin isolated, otherwise up to 4 (as in the PoC).

### Compatibility verdict

`compat/` returns `{verdict: 'ok' | 'maybe' | 'no', checks: [{id, label, status, detail}]}`. Checks: secure context; WebGPU API; adapter obtained; `shader-f16`; max storage buffer binding >= 128 MiB; tiny ONNX WebGPU probe passes within 60 s; module workers; Cache Storage and IndexedDB; storage quota vs chosen pack size; `navigator.deviceMemory` when exposed; Web Audio; user-agent family (iOS/iPadOS WebKit flagged `maybe` with the reason: WebGPU and memory limits unverified, to check). `no` = a hard requirement failed (reason shown in plain words). `maybe` = runs but something is unverified or marginal; user may continue. The result screen has Copy report. Verified-device notes live in `docs/compat.md`; unverified entries are marked "to check".

### Audio

- `sample prep`: stereo WAV from SA3 → mono Float32 at 44.1 kHz, trim leading/trailing silence, short fade-out, normalize; stored as Float32 PCM in IndexedDB per track.
- `pitch detection`: autocorrelation or YIN on the sustained region; returns MIDI note (fractional) + confidence; low confidence falls back to C4 and is flagged in the UI.
- `voice`: `AudioBufferSourceNode` with `playbackRate = 2^((note - root)/12)`, gain envelope (short attack, release at note end). Notes longer than the sample end with the sample.
- `scheduler`: look-ahead scheduler over the pattern loop at the project tempo; a play-head position for the UI; notes starting while playing or auditioned from the piano keys.
- Generation prompt template: `"<user prompt>, single sustained note, dry, no reverb, no drums"`.

### Project model and persistence

`Project {id, name, bpm, key, bars(1-4), tracks[]}`, `Track {id, name, muted, sampleId|null, rootMidi, notes[{id, midi, start(16ths), length}]}`. Notes snap to 1/16. Autosave on change (debounced 500 ms) to IndexedDB; samples stored separately by id. Load on start; "New project" and "Delete project" buttons with confirmation. One project slot for the demo.

### Screens (portrait, 412 px design width)

1. Compatibility gate: verdict, per-check list, Continue / Copy report / Open Debug.
2. Tracks (home): header with project name, readouts (position, tempo, key, bars), track rows (name, mute, root note, waveform thumbnail, Open roll, Generate), Add track; transport bar (stop, play, loop indicator); bottom nav: Tracks · Mix · Models · Debug.
3. Piano roll: note grid with piano-key column, visible tools (Draw, Erase), length -/+, transpose -/+ for selected note, Delete, Clear, grid is 1/16; tap key = audition; playhead; back button.
4. Generate sheet: prompt, quick-prompt chips, model (Small SFX / Small Music / Medium, shows installed state), length 2/3/4 s, steps (default 8), seed (random button), Generate with violet button; progress with stage names and elapsed time; Cancel; result shows waveform, detected root, ±1 semitone, Play, Re-generate.
5. Models: per-model size, installed state, Download / Delete (confirmation), progress, persistence status, storage usage, Free model memory, Delete all models, Clear all app data (models, project, samples; confirmation). Nothing is stored until the user taps Download. The shared encoder is removed with the last model that needs it.
6. Debug: level-filtered live log; GPU adapter info and limits; storage estimate; per-generation timing table (load, conditioning, each step, decode, prep); Copy report, Download report (JSON), Clear.

### Logging

Every module logs through `log/`: `{t, level, scope, message, data?}` in a ring buffer (5000 entries), also mirrored to `console`. Worker messages carry log entries and stage timings. Uncaught errors and unhandled rejections are captured. The report JSON contains: app version/build time, user agent, compat verdict + checks, GPU info, storage estimate, installed packs, last 5 generation timing records, and the log.

## Verification

- Vitest and svelte-check: pitch detection on synthesized tones, sample prep, playback-rate maths, scheduler timing with a fake clock, project persistence round trip (fake IndexedDB), compat verdict rules with fake environments, manifest/pack install state, log ring buffer and report.
- Headless Chromium smoke (Playwright Chromium on the Deck, Vulkan WebGPU flags as in the PoC): the app loads from the HTTPS server, compat passes, Small installs, generation produces a sample, reload keeps the project and the sample, and a second visit with the network blocked still opens and plays. Phone behavior is checked by the user.
- Targets: Linux Chrome on the Deck (verified by smoke); Android Chrome on a Pixel 10 Pro XL (user-reported working for the PoC, to confirm for this app). iOS/Safari and other phones: to check; the app reports its own verdict.
